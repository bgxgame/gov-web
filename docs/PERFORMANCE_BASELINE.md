# 前端性能基线

## 1. 本轮目标
- 为首页地图、路由切换、构建产物体积建立稳定基线
- 让“慢在哪里”能够被持续观测，而不是靠体感判断
- 为后续地图下钻第二阶段、资源精简、接口治理提供对照依据

## 2. 当前已启用的性能措施
- Element Plus 按需引入
- Vue、Pinia、Vue Router、Axios、Element Plus 做基础拆包
- ECharts 仅在地图相关页面加载
- 高频查询使用 `cancelKey` 取消旧请求
- 路由切换提供轻量进度条和慢路由日志
- 地图按层级加载 GeoJSON，不再一次性加载全部点位

## 3. 建议持续关注的指标
| 指标 | 建议阈值 | 说明 |
| --- | --- | --- |
| 首次路由完成耗时 | 小于 1600ms | 冷启动时允许略高 |
| 常规菜单切换耗时 | 小于 800ms | 用户体感阈值 |
| 慢请求阈值 | 小于 800ms | 对齐前端告警阈值 |
| 主包体积 | 持续下降 | 重点关注地图与 UI 库影响 |
| 地图资源单文件大小 | 越小越好 | 优先控制市县级资源 |

## 4. 分析方法
1. 运行 `npm run build`
2. 运行 `npm run build:stats`
3. 查看 `logs/build-stats-latest.md`
4. 对照前一次构建结果，确认是否有异常回升
5. 如发现菜单切换慢，再结合 `window.__GOV_APP_LOGS__` 与后端 `perf.log` 联查

## 5. 后续优化方向
- 继续细分地图资源，避免首页首次进入拉入县级数据
- 对地图详情与右侧面板考虑更细的按需加载
- 评估对高频系统页做更细粒度代码分割
- 对接口分页默认参数、筛选联动策略继续减压
